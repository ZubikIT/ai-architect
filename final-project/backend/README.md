# `/backend` — GraphRAG-ядро платформы цифровых сотрудников

Рабочая реализация к [`../docs/mvp.md`](../docs/mvp.md). Закрывает три требования ТЗ: обязательный **GraphRAG** ([ADR-0012](../docs/adr/0012-graph-db.md), [ADR-0013](../docs/adr/0013-graphrag-strategiya.md)), критичный сценарий безопасности «User B не получает закрытый документ» ([ADR-0016](../docs/adr/0016-acl-na-uzlah-grafa.md)) и критичное «**state machine, а не линейные скрипты**» — мультиагентный слой на LangGraph ([ADR-0015](../docs/adr/0015-topologiya-mas-cifrovye-sotrudniki.md)).

## Что делает граф, чего не делает плоский вектор

Вопрос «сколько дней основной отпуск?» векторным поиском находит пункт ЛПА-01: «28 календарных дней». Этот пункт **отменён** приказом ЛПА-04 («30 дней»), но текстуально отменяющий документ похож на десятки других — гарантии, что он попадёт в top-k, нет. Ребро `ОТМЕНЯЕТ` добавляет его в контекст **безусловно** и помечает исходный пункт как недействующий:

```
$ SUFLER_USE_LLM=0 python -m sufler.cli "Сколько дней основной ежегодный отпуск?"

⚠️ ЛПА-01 «1. Продолжительность отпуска» отменён документом ЛПА-04 · 1. Продолжительность отпуска.

Источники:
  - lpa-otpusk.md · 1. Продолжительность отпуска  ← ОТМЕНЁН
  - lpa-otpusk-izmeneniya.md · 1. Продолжительность отпуска  ← действующая редакция
```

Это и есть «потеря контекста» из формулировки ТЗ: без графа сотрудник получает отменённую норму без единой оговорки. Контрольный замер зафиксирован тестом `test_graph_disabled_loses_the_annotation` — с `SUFLER_GRAPH=0` пометка исчезает.

### Онтология (4 типа узлов, рекомендация занятия 32)

```
(:Документ)-[:СОДЕРЖИТ]->(:Чанк)
(:Чанк)-[:ОТМЕНЯЕТ]->(:Чанк)          отменяющая редакция → отменённый пункт
(:Чанк)-[:ССЫЛАЕТСЯ_НА {clause}]->(:Документ)
(:Чанк|:Документ)-[:ДОСТУПЕН_РОЛИ]->(:Роль)
```

**Три** бэкенда за одним интерфейсом: `PgGraphStore` (боевой путь — рекурсивные CTE, `SUFLER_GRAPH_DSN`), `Neo4jGraphStore` (`NEO4J_URI`) и `InMemoryGraphStore` (офлайн-демо и тесты). Семантика ACL у всех одна и проверена паритетом: ноль расхождений по каждому чанку как seed, на трёх наборах ролей, включая аннотации.

Выбор сделан замером, а не умолчанием ([ADR-0028](../docs/adr/0028-grafovoe-hranilishche.md), [разбор](../docs/graph-backends.md)): из четырёх критериев **три не разделили** — качество одинаково, время обхода при `hops=2` составляет около 1 % ответа. Решили изоляция окружений (в Neo4j Community база одна на инстанс) и стоимость второго stateful-хранилища. `SUFLER_GRAPH_BACKEND=auto|neo4j|postgres|memory` позволяет потребовать конкретный — без этого сравнивать было бы нечем.

## Безопасность доступа

ACL-предикат применяется **на каждом узле пути обхода**, а не к финальной выдаче: иначе закрытый документ утекает через структуру связей — существование, название, соседей. Отдельное следствие, зафиксированное тестом: **факт отмены не раскрывается**, если отменяющий документ недоступен субъекту.

```bash
# User B (роль all) — закрытого ЛПА-03 нет ни в ответе, ни в контексте LLM
SUFLER_USE_LLM=0 python -m sufler.cli "Как обрабатываются персональные данные командированного?"
# User A (роль legal) — тот же документ приходит по ребру ССЫЛАЕТСЯ_НА
SUFLER_USE_LLM=0 python -m sufler.cli --roles legal "Как обрабатываются персональные данные командированного?"
```

### Откуда берутся роли

С заданным `OIDC_JWKS_URL` роли приходят **только из подписанного токена** Keycloak, а поле `roles` в теле запроса не влияет на доступ вообще — не «влияет меньше», а не влияет ([ADR-0016](../docs/adr/0016-acl-na-uzlah-grafa.md), урок 26). До этого сценарий «User B не получает закрытый документ» держался на честном клиенте: достаточно было прислать `roles: ["legal"]`.

```bash
curl -H "Authorization: Bearer $TOKEN" -d '{"question":"...","roles":["legal"]}' :8080/ask
#                                            ↑ токен решает        ↑ игнорируется
```

Проверяется подпись по JWKS (кэш ключей с TTL, обновление на ротацию `kid`), `exp`/`nbf`, при заданных значениях — `aud` и `iss`. Алгоритмы берутся из **фиксированного списка асимметричных**, а не из заголовка токена: это закрывает подмену `RS256 → HS256` и `alg: none`. Негативные случаи — в [`tests/test_auth.py`](tests/test_auth.py), подделка собирается побайтово (через `jwt.encode` её не сделать — библиотека не даёт).

> Без `OIDC_JWKS_URL` сервис работает в **dev-режиме**: роли из тела запроса, допустимо только в доверенном контуре. Режим виден снаружи — `/healthz` отвечает `{"auth": "dev"}`. Молчаливый dev-режим в проде опаснее отсутствующего. Роли в CLI — та же отладочная история: CLI не является точкой входа пользователя.

## Мультиагентный слой: «цифровые сотрудники»

ТЗ требует state machine, а не линейную цепочку. Линейного пути здесь нет:

```
START → supervisor ──(есть кому поручить)──→ worker ──┐
          │                                            │
          └──(очередь пуста | лимит исчерпан)──→ synthesize → END
                                 ▲                     │
                                 └─────────────────────┘
```

Есть состояние (досье запроса), ветвление супервизора, цикл «супервизор → сотрудник → супервизор», лимиты и checkpoint'ы. Структура графа проверяется тестом `test_execution_graph_has_branch_and_cycle` — утверждение о цикле не голословно.

**Четыре роли** ([`roles.py`](sufler/roles.py)): Кадровик, Юрист по ЛПА, Инженер по техдокументации, Комплаенс-контролёр. Добавление «сотрудника» — это запись в конфигурации, граф выполнения не меняется.

**Маршрутизация детерминирована.** Сначала правила по ключевым словам, LLM-классификация — только для запросов, не попавших ни в одно правило, и её результат валидируется по списку ролей. Целью агента нельзя манипулировать текстом, если цель выбрана не текстом (ASI01). При низкой уверенности запрос уходит веером двум ролям — вопрос на стыке компетенций не теряет половину ответа.

**Права агента ≤ прав пользователя.** Мандат роли (`grants`) — это потолок, а не источник прав: фактический доступ = права пользователя ∩ мандат роли, и пересечение считается в [`tools.py`](sufler/tools.py), а не в промпте. Промпт — текст, его можно переубедить; пересечение множеств переубедить нельзя.

```bash
# один и тот же пользователь (роль legal), один и тот же вопрос — но роль агента решает
SUFLER_USE_LLM=0 python -m sufler.cli --mas --trace --roles legal \
  "Как обрабатываются персональные данные командированного работника?"
```

```
Маршрут (rules, уверенность 0.5): Кадровик → 7 п. правами ['all'],
                                  Комплаенс-контролёр → 8 п. правами ['legal']
Бюджет: шагов 2, вызовов инструментов 2, ~1630 токенов

ReAct-trace:
  [0] supervisor        Action: route(['hr', 'compliance'])
  [1] Кадровик          Action: graph_search(query="...", roles=['all'])      → 7 пунктов
  [2] Комплаенс-контролёр Action: graph_search(query="...", roles=['legal'])  → 8 пунктов
  [3] supervisor        Action: synthesize(sources=9)
```

Кадровик не дотянулся до ЛПА-03, хотя пользователь имеет право `legal`: кадровый мандат этой роли не содержит — least privilege (ASI03), тест `test_hr_agent_cannot_reach_legal_contour`. Закрытый документ приносит только Комплаенс-контролёр, и в источниках видно, какой агент его принёс — атрибуция действия для аудита.

**Лимиты не декоративные.** Потолок шагов, вызовов инструментов и бюджет токенов; при исчерпании платформа деградирует явно — сводит найденное и называет, кого не успела опросить («Ответ неполный: исчерпан лимит шагов (1); не опрошены: Комплаенс-контролёр»). Молчаливый обрыв — это LLM06 Unbounded Consumption и каскадный отказ ASI08.

**Состояние — в checkpointer**, ключ `thread_id` = `request_id`: разбор инцидента воспроизводим по шагам, и адресуется он тем же идентификатором, что и записи аудита. PostgreSQL при заданном `DATABASE_URL`, иначе in-memory. Input-guardrail стоит **до** графа: отклонённый запрос не создаёт checkpoint, иначе отравленный ввод осел бы в долговечном состоянии (ASI06).

**Чего у слоя ещё нет:** мутирующих инструментов (все read-only, HITL по [ADR-0015](../docs/adr/0015-topologiya-mas-cifrovye-sotrudniki.md) правило 6 не понадобился) и замеров на golden set — точность маршрутизации, прирост качества против монолита и стоимость запроса не измерены, поэтому **ADR-0015 остаётся в статусе `proposed`**. Пока измерений нет, честная формулировка для защиты: топология выбрана по доменной декомпозиции и модели доступа, а не по доказанному приросту качества.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# офлайн, без LLM и без инфраструктуры (граф — in-memory)
SUFLER_USE_LLM=0 python -m sufler.cli "Сколько дней основной ежегодный отпуск?"

# с боевым стеком
export SUFLER_GRAPH_DSN=postgresql://platform:...@localhost:5432/platform   # граф (ADR-0028)

export OPENAI_BASE_URL=http://<vllm-host>:8000/v1 SUFLER_USE_LLM=1

# реранк на сервисе платформы вместо локального CPU (ADR-0027).
# Без этих переменных работает локальный cross-encoder — но он не проходит
# гейт «честный отказ»: его оценки не калиброваны и порога не держат.
export SUFLER_RERANK_URL=http://<infinity-host>:7997     # Vault: secret/zubriq-console/env
export SUFLER_RERANK_API_KEY=...                         #   EMBEDDINGS_URL / EMBEDDINGS_API_KEY

python -m sufler.cli --stats          # проверить, что граф построен
uvicorn sufler.api:app --port 8080
```

Весь стек разом — [`../infra/docker-compose.yml`](../infra/README.md).

## Тесты

```bash
pytest -q      # 92 теста офлайн (103 со стеком); при первом запуске тянет модели эмбеддера и реранкера

# + 5 тестов боевого графа (пропускаются без стека)
docker compose -f ../infra/docker-compose.yml --profile core up -d neo4j qdrant
SUFLER_GRAPH_DSN=postgresql://... NEO4J_URI=bolt://localhost:7687 NEO4J_PASSWORD=... QDRANT_URL=http://localhost:6333 pytest -q
```

Покрыто: паритет графовых бэкендов (обход и аннотации по каждому чанку × три набора ролей), сторож цикла в рекурсивном CTE (замером промежуточной работы — первый тест на это свойство проходил и со снятым сторожем, то есть ничего не проверял), отказ сервиса ранжирования (503 вместо пустой выдачи, текст отличим от отказа по корпусу; повтор на обрыве и 5xx, отсутствие повтора на таймауте и 4xx), порядок оценок реранкера (сервис возвращает их по рангу, а вызывающему нужен порядок исходных пар — ошибка, которая не падает, а молча ухудшает выдачу), применение порога отказа только к калиброванной модели, эффект графа и контрольный замер без него, «User B» (на обоих путях — одиночном и мультиагентном), доступ роли `legal` через граф, deny-by-default, сокрытие отмены закрытым документом, блокировка prompt injection, структура графа выполнения (ветвление и цикл), детерминированность маршрутизации, least privilege роли агента, деградация по лимитам, сохранение состояния в checkpointer, граница доверия (роли из подписи, игнорирование ролей из тела, истёкший/бессрочный/чужой токен, подмена алгоритма, `alg: none`, неизвестный `kid`, `aud`/`iss`), наблюдаемость (`trace_id` = `request_id`, структура трейса на обоих путях, отсутствие содержимого в атрибутах, маска на экспорте, доменные метрики). На живом Neo4j дополнительно: паритет с in-memory по всему корпусу для трёх наборов ролей (обход и аннотации), глубина обхода по цепочке отмен, оба направления ребра `ОТМЕНЯЕТ`, сопоставимость `/graph/stats`.

## Наблюдаемость: `request_id` открывает трейс

`request_id` в ответе — это `uuid4().hex`, то есть ровно те же 128 бит, что и `trace_id` OpenTelemetry. Поэтому идентификатор не «прокидывается атрибутом», а **становится** идентификатором трейса ([ADR-0017](../docs/adr/0017-observability.md)): значение из ответа вставляется в поиск Jaeger и открывает разложение запроса по шагам. Цена решения — собственный генератор идентификаторов и отказ от авто-инструментации FastAPI: её серверный спан открывается раньше, чем известен `request_id`.

```
ask                     1533.6 ms  {outcome: ok, path: rag, sources: 5,
                                    graph_contribution: true, cancellation_flagged: true}
  guardrail.input          0.0 ms
  retrieve              1532.8 ms  {chunks: 5}
    retrieve.hybrid     1523.6 ms  {seeds: 5}
    graph.expand           6.2 ms  {backend: neo4j, hops: 2, expansions: 0}
    graph.annotate         2.4 ms  {annotated: 2}
  guardrail.output         0.1 ms
```

Первый же замер отвечает на вопрос, который обычно задают GraphRAG: **граф стоит 8 мс из 1,5 с**, а полторы секунды уходят на эмбеддинг и реранк на CPU. Обвинение графа в латентности не подтверждается — и это видно из трейса, а не из рассуждений.

На мультиагентном пути трейс содержит 13 спанов: `agents.ask` → `supervisor.route` → `agent.hr` и `agent.compliance` (каждый со своим `tool.graph_search` и фактическими правами) → `supervisor.synthesize`. ReAct-шаги лежат событиями спана теми же тремя полями, что и в UI.

**Содержимое запроса в трейс не попадает** — ни вопрос, ни контекст, ни ответ. Jaeger в контуре доступен шире, чем сами документы, а спан с промптом внутри — это фрагменты ЛПА и ПДн ([Data Flow](../docs/diagrams/data-flow.md): трейсы — поверхность утечки). `SUFLER_OTEL_CONTENT=1` включает текст для отладки, и тогда он проходит ту же PII-маску, что и ответ. Страховка — маска на экспорте: она применяется ко всем строковым атрибутам и событиям **до** отправки, что бы ни записал вызывающий код.

Разложение по шагам — не украшение: на нём построен [нагрузочный отчёт](../docs/load-report.md), и оно же ответило, где узкое место (cross-encoder rerank, 76–90 % времени ответа; граф — около 1 %).

Доменные метрики (`/metrics`, дашборд [`infra/grafana`](../infra/grafana/dashboards/graphrag.json)) отвечают на вопрос «а работает ли граф в проде»: `sufler_answers_total{cancellation="yes"}` — доля ответов, где сработало ребро `ОТМЕНЯЕТ`. Ноль при живом трафике означает, что граф не работает, как бы хорошо он ни выглядел на демо.

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=localhost:4317   # без переменной спаны никуда не уходят
python -m sufler.cli "Сколько дней основной ежегодный отпуск?"
# request_id: 7b889ec9... → http://localhost:16686/trace/7b889ec9...
```

## Живой прогон: что нашёл боевой бэкенд

Пока граф работал только в in-memory-режиме, Neo4j-бэкенд был написан, но не проверен. Первый же прогон на поднятом стеке ([`../infra`](../infra/README.md)) показал три расхождения — все три исправлены, на каждое есть тест:

| Что расходилось | Чем это грозило |
|---|---|
| `expand` выполнял **один** запрос и игнорировал `SUFLER_GRAPH_HOPS` | боевой путь молча терял глубину: цепочка «отмена отмены» обрывалась на первом звене, а in-memory её проходил |
| в Cypher не было ветки `(seed)-[:ОТМЕНЯЕТ]->(other)` | от отменяющего пункта не был виден отменённый — одно из двух направлений ребра просто отсутствовало |
| `/graph/stats` считал служебные рёбра (`СОДЕРЖИТ`, `ДОСТУПЕН_РОЛИ`) | 4 против 52 на одном и том же корпусе: показатели двух бэкендов были несопоставимы |

Плюс две вещи, которые видно только на стеке: сервис `qdrant` в compose **никем не использовался** (индекс жил в процессе, а поднятый Qdrant стоял пустым) — теперь подключается через `QDRANT_URL`; драйвер Neo4j **не закрывался** — в долгоживущем сервисе это утечка пула сокетов, закрывается на остановке (`lifespan`).

Смысл не в трёх багах, а в том, что **доказательства безопасности, полученные на in-memory, к Neo4j не относятся автоматически**. Поэтому паритет бэкендов теперь проверяется тестом по каждому чанку корпуса для трёх наборов ролей — и обход, и аннотации.

Четвёртая находка появилась, когда тесты пошли против живой базы: фикстура корпуса была сессионной, а тест на сокрытие отмены меняет ACL ЛПА-04 прямо в объектах. Мутация доставалась следующим тестам, и тест паритета записывал изменённый корпус **в Neo4j** — ЛПА-04 становился закрытым, и демонстрация «28 → 30 дней» переставала работать до следующей переиндексации. В офлайн-режиме это не проявлялось никак. Фикстура сделана пофайловой; разбор markdown стоит миллисекунды.

```bash
# демо-режим: без стека, граф и вектор встроенные
SUFLER_USE_LLM=0 python -m sufler.cli "Сколько дней основной ежегодный отпуск?"

# боевой режим: тот же код, живые Neo4j и Qdrant
export NEO4J_URI=bolt://localhost:7687 NEO4J_PASSWORD=... QDRANT_URL=http://localhost:6333
python -m sufler.cli --stats
# {'backend': 'neo4j', 'nodes': 19, 'documents': 4, 'edges': 4, 'cancels': 1, 'references': 3}
```

## Потоковый ответ (SSE)

`POST /ask/stream` отдаёт `text/event-stream`: `meta` → `sources` → `token`* → `note`* → `done`.

**Источники уходят раньше текста** — для корпоративного ассистента цитата важнее скорости появления первого слова: пользователь сразу видит, на чём будет основан ответ, и может остановиться, если основание не то. Пометка об отмене приходит отдельным событием `note`, а не хвостом абзаца, — интерфейс обязан показать её заметно.

```bash
curl -sN -X POST :8080/ask/stream -H 'content-type: application/json' \
  -d '{"question":"Сколько дней основной ежегодный отпуск?","roles":["all"]}'
```

Две вещи, которые в потоке сложнее, чем кажутся:

- **Маска ПДн.** Маскировать каждый токен отдельно нельзя: шаблон почти всегда разорван границей (`ivan@` + `example.com`). Поэтому маска накладывается на накопленный текст, а наружу идёт устойчивый префикс — всё, кроме последних 64 символов. Шаблон длиннее окна проскочит; это названо прямо в [`guardrails.py`](sufler/guardrails.py), а не спрятано.
- **Спаны через `yield`.** Контекстные переменные не переживают `yield` — ASGI-сервер шагает генератор в разных контекстах, и `with`-обёртка падает с «Token was created in a different Context». Поэтому в потоковом пути родитель спана передаётся явно, а активируется спан только на шагах без `yield` ([`telemetry.py`](sufler/telemetry.py)). Регрессия закрыта тестом: трейс обязан остаться одним и закрытым.

Потоковый путь идёт через ту же функцию подготовки, что и обычный: разойдись они — разошлись бы проверка прав и пометки об отменах. Инварианты доступа проверены на нём отдельно ([`test_streaming.py`](tests/test_streaming.py)).

## Качество: golden set и гейты

```bash
python -m tools.eval          # код 1, если гейты приёмки не пройдены
```

14 кейсов в [`eval/golden.yaml`](eval/golden.yaml), метрики считаются **без LLM** — recall и precision из совпадения с эталонными пунктами, нарушения ACL из факта появления закрытого документа, точность маршрутизации из решения супервизора. Результаты и разбор — [отчёт](../docs/eval-report.md).

Прогон нашёл две вещи, которых не видели ни тесты, ни нагрузочный замер: система **отвечала на любой вопрос** (порога релевантности не было, ответ про спутники приходил со ссылками на положение об отпуске) и **текст отказа выдавал существование закрытого документа**. Обе закрыты. Порог сначала пришлось ставить на косинус эмбеддера, а не на оценку реранкера: логиты `ms-marco` на русском корпусе не разделяют релевантное и нерелевантное вовсе. После переноса реранка на сервис платформы ([ADR-0027](../docs/adr/0027-konveyer-ranzhirovaniya.md)) порог переехал на релевантность — зазор 0,9915 против прежних 0,216 по косинусу.

Прогон нашёл и третье, уже в самом эталоне: кейс, где ответа для роли в корпусе нет, проверял только «не протёк ли закрытый документ» и засчитывал как успех выдачу из шести посторонних пунктов. Теперь `refusal_pass` — гейт приёмки, и **локальная конфигурация его не проходит**.

## Ограничения текущей реализации

- **Эмбеддер остаётся лёгкой CPU-моделью.** Реранк перенесён на сервис платформы ([ADR-0027](../docs/adr/0027-konveyer-ranzhirovaniya.md)), и после этого эмбеддер стал вторым по стоимости шагом — 24 мс, 12 % ответа против прежних 3,6 %. Тот же сервис отдаёт `bge-m3`; перенос требует переиндексации (1024 измерения против 384) и пересчёта косинусного порога. Qdrant работает и встроенным (`:memory:`, демо), и как self-hosted сервер (`QDRANT_URL`) — проверены оба пути.
- **Без `SUFLER_RERANK_URL` конфигурация не проходит приёмку.** Локальный cross-encoder оставлен как офлайн-путь для тестов и демонстрации без сети; гейт «честный отказ» на нём даёт 0,5, потому что его оценки не калиброваны. Это названо здесь, а не спрятано в отчёте: офлайн-режим годится для разработки, но не выдаёт себя за рабочую конфигурацию.
- **При недоступности сервиса ранжирования запрос отклоняется явно** — 503 с текстом, который отделяет сбой от пустой выдачи ([ADR-0027](../docs/adr/0027-konveyer-ranzhirovaniya.md#отказ-сервиса-ранжирования)). Молчаливый откат на локальную модель отвергнут: вместе с ней тихо перестал бы работать порог отказа. Размыкателя цепи нет — при длительном отказе каждый запрос всё равно ждёт таймаут.
- **Коллекция Qdrant пересоздаётся на старте процесса**: для демо это правильно (индекс — производный артефакт), для прода индексация обязана быть отдельной задачей с отдельной учётной записью ([ADR-0016](../docs/adr/0016-acl-na-uzlah-grafa.md)).
- **Мультимодальный ingestion не реализован**: работает первая ступень каскада (текстовый слой), layout-парсер и VL-разбор сканов/чертежей — по [ADR-0014](../docs/adr/0014-multimodalnyy-ingestion.md). Поля `extracted_by` и `confidence` уже есть в контракте чанка.
- **Мультиагентный слой не замерен**: реализован ([`mas.py`](sufler/mas.py)), но точность маршрутизации, прирост против монолита и стоимость запроса не измерены на golden set — критерии перехода ADR-0015 в `accepted` не выполнены.
- **Checkpointer PostgreSQL опционален**: без пакета `langgraph-checkpoint-postgres` состояние живёт в памяти процесса, и при перезапуске воспроизводимость теряется.
- **Трейсы уходят только в Jaeger:** экспорт в Langfuse ([ADR-0017](../docs/adr/0017-observability.md), вариант 4) не подключён, поэтому LLM-семантики — faithfulness, стоимость, дрейф — в наблюдаемости пока нет.
- **Метрик качества нет**: RAGAS/LLM-as-a-Judge не подключены, дашборд показывает Golden Signals и доменные метрики GraphRAG/MAS, но не качество ответов.
- **JWT проверяется, но Keycloak рядом не поднят**: валидация закрыта тестами на сгенерированных ключах, против живого realm'а не прогонялась. Отзыв токена до истечения `exp` не поддерживается (нет интроспекции) — окно равно времени жизни токена.
- Экстракция связей — правилами; LLM-экстрактор сущностей ([ADR-0013](../docs/adr/0013-graphrag-strategiya.md)) не подключён.
