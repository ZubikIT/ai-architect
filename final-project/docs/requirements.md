# Требования (FR / NFR)

> **Редакция 1.0 переписана целиком.** Черновик 0.1 строился вокруг Open WebUI, Onyx и 2× H100 — ни одного из трёх в реальности нет. Здесь требования к **работающей платформе**, и у каждого проставлено фактическое состояние.
>
> Обозначения: ✅ работает в платформе · 🟦 реализовано в [`backend/`](../backend/), в платформу не встроено · 🟡 спроектировано · ❌ нет.

## Функциональные требования

### FR-1. Ответ по корпоративным ЛПА

| | Требование | Состояние |
|---|---|---|
| FR-1.1 | Ответ **только по контексту**, иначе отказ | 🟦 промпт + порог релевантности |
| FR-1.2 | **Цитирование пункта**: код документа и номер, устойчивые к перечанкингу | 🟦 `doc_code` + `ordinal` в каждом источнике |
| FR-1.3 | **Пометка об отменяющей редакции**: если пункт отменён, ответ обязан это сказать | 🟦 рёбра `ОТМЕНЯЕТ`, гейт `cancellation_pass = 1,0` |
| FR-1.4 | Отказ **не раскрывает существование** закрытого документа | 🟦 единый текст на отказ по правам и по релевантности |
| FR-1.5 | Стриминг ответа | 🟦 SSE, трейс остаётся одним и закрытым |

FR-1.4 неочевиден и потому назван отдельно. Формулировка «не нашёл пунктов **для вашего уровня доступа**» сообщает, что документ существует, — это утечка через факт существования, против которой построен весь ACL. Различаются два отказа там, где это нужно для эксплуатации: в метриках и трейсе, а не в ответе.

### FR-2. Retrieval и ранжирование ([ADR-0027](adr/0027-konveyer-ranzhirovaniya.md))

| | Требование | Состояние |
|---|---|---|
| FR-2.1 | **Hybrid search**: dense + BM25, объединение RRF | ✅ в платформе (`kb_chunks`, pgvector + FTS) · 🟦 в backend |
| FR-2.2 | **Реранк калиброванной моделью** — обязателен, потому что на нём стоит порог отказа | ✅ сервис платформы `bge-reranker-v2-m3` |
| FR-2.3 | **Порог отказа на релевантности**, а не на близости | 🟦 `SUFLER_MIN_RERANK_SCORE`, зазор 0,9915 |
| FR-2.4 | **ACL pre-filter до ранжирования** — наружу уходят только разрешённые кандидаты | 🟦 |
| FR-2.6 | **Отказ зависимости отличим от пустой выдачи**: сбой сервиса ранжирования — 503, а не «не нашёл пунктов» | 🟦 [ADR-0027](adr/0027-konveyer-ranzhirovaniya.md#отказ-сервиса-ранжирования) |
| FR-2.5 | Чанк несёт **написанную человеком тематическую метку** (название пункта или ближайшего раздела) плюс адрес | 🟦 сделано. Замер на кодексах: название **+16,4 п.п. hit@1**, адрес +1,6 — не в сумме, название адрес заменяет; адрес нужен ради hit@6 ([`eval/ab-anchor.md`](eval/ab-anchor.md)). Риск переноса на НПА измерен: без названий эффект падает до +1,6 |

FR-2.2 сформулировано через **калиброванность**, а не через имя модели, потому что именно это свойство критично: оценки `ms-marco` на русском корпусе не разделяют «в корпусе» и «вне» (8,2658 против 8,9686), и порог на них поставить нельзя ни при какой скорости.

### FR-3. Граф знаний и GraphRAG ([ADR-0012](adr/0012-graph-db.md), [ADR-0013](adr/0013-graphrag-strategiya.md))

| | Требование | Состояние |
|---|---|---|
| FR-3.1 | Онтология: `Документ` / `Чанк` / `Роль`; рёбра `СОДЕРЖИТ`, `ОТМЕНЯЕТ`, `ССЫЛАЕТСЯ_НА`, `ДОСТУПЕН_РОЛИ` | 🟦 |
| FR-3.2 | Порядок **vector-first → обход 1–2 хопа → реранк** | 🟦 |
| FR-3.3 | Связи извлекаются **правилами**, а не моделью — воспроизводимо и объяснимо | 🟦 [`links.py`](../backend/sufler/links.py) |
| FR-3.4 | Граф даёт **измеримый эффект**, а не декоративен | 🟦 контрольный замер: без графа аннотация об отмене теряется |
| FR-3.5 | Граф на **реальном корпусе НПА** | ❌ [задача zubriq/kb-graph#1](https://git.artcloud.by/zubriq/kb-graph/-/work_items/1) |

### FR-4. Цифровые сотрудники ([ADR-0015](adr/0015-topologiya-mas-cifrovye-sotrudniki.md))

| | Требование | Состояние |
|---|---|---|
| FR-4.1 | **State machine**, а не линейные цепочки — требование ТЗ | 🟦 LangGraph, цикл супервизор ⇄ работник |
| FR-4.2 | Супервизор маршрутизирует **детерминированно**, без вызова модели | 🟦 13/13, 0,1 мс на маршрутизацию |
| FR-4.3 | **Мандат прав роли**: права агента ⊆ прав пользователя, сужение считается **в инструменте**, а не в промпте | 🟦 тест `test_hr_agent_cannot_reach_legal_contour` |
| FR-4.4 | **Лимиты** шагов, вызовов инструментов и бюджета токенов | 🟦 без потолка это LLM06 Unbounded Consumption |
| FR-4.5 | **Persistence состояния** по `request_id` — возобновление и аудит | 🟦 checkpointer; PostgreSQL опционален |
| FR-4.6 | Human-in-the-loop на необратимых действиях | 🟡 необратимых действий в текущем наборе инструментов нет |

### FR-5. Права и идентификация ([ADR-0016](adr/0016-acl-na-uzlah-grafa.md), [ADR-0021](adr/0021-identifikaciya-keycloak-federaciya.md))

| | Требование | Состояние |
|---|---|---|
| FR-5.1 | Роли берутся **из подписи токена**, а не из тела запроса | 🟦 JWKS, фиксированный список асимметричных алгоритмов |
| FR-5.2 | **Deny-by-default**: нет явного разрешения — нет доступа | 🟦 |
| FR-5.3 | **ACL на каждом узле пути обхода**, не на выдаче | 🟦 |
| FR-5.4 | Факт отмены **скрыт**, если отменяющий документ недоступен | 🟦 |
| FR-5.5 | SSO, группы каталога в токене | ✅ Keycloak + федерация FreeIPA |
| FR-5.6 | **Аудит-лог** доступа и отказов (№ 99-З) | 🟦 отказ — такое же событие, как выдача |

FR-5.1 — граница доверия. Без неё клиент назначает себе роли сам, и весь остальной ACL становится украшением.

| Атрибут | Цель | Факт | Источник |
|---|---|---|---|
| **Latency p95**, короткий ответ | ≤ 5 с | **1,0 с** на 8 клиентах (retrieval); **3,4 с** на 2 клиентах с генерацией | [замер](load-report.md#реранк-вынесен-на-сервис-платформы--повторный-замер) |
| **Latency p95**, агентный | ≤ 15 с | **2,4 с** на 8 клиентах (retrieval); **10,3 с** на 2 с генерацией | там же |
| **Latency p95** строгая ([ADR-0017](adr/0017-observability.md)) | ≤ 3 с без цикла, ≤ 8 с с циклом | retrieval держит оба на 8 клиентах; **с генерацией строгий агентный SLO нарушается на первом клиенте** | там же |
| **Throughput** | ⚠ целевой профиль не задан | 11,03 RPS на 8 клиентах (retrieval); предел новой конфигурации **не найден** | там же |
| **Доступность** | 99,5 % в рабочие часы | ⚠ не измерена. **Инференс без резерва** — один GPU-бокс | [техдолг № 6](../../zubriq-platform/docs/operations.md#известный-техдолг) |
| **Масштабируемость** | горизонтальный рост реплик | для retrieval после [ADR-0027](adr/0027-konveyer-ranzhirovaniya.md) **снова осмыслен и вертикальный**: узкое место переехало из ядер хоста в общий сервис | [замер](load-report.md#главное--не-ускорение-а-то-что-изменился-характер-насыщения) |
| **Безопасность** | нулевой egress закрытого контура; секреты в Vault; TLS | ✅ барьер один и проверяем — поле `models`. ⚠ барьер **логический, не сетевой**: защита в глубину однослойная | [ADR-0020](adr/0020-dva-rezhima-dostupa.md) |
| **Приватность / № 99-З** | данные в контуре; ретеншн; удаление по требованию | ✅ контур. ❌ **ретеншн не определён**, сквозной процедуры удаления из всех мест хранения нет | [security](../../zubriq-platform/docs/security.md) |
| **Качество** | recall ≥ 0,85 · ACL = 0 · отмены = 1,0 · отказ = 1,0 · маршрутизация ≥ 0,9 | **все гейты пройдены**; прогон возвращает код 1 при провале | [golden set](eval-report.md) |
| **Объяснимость** | цитирование пункта; трейс шагов | ✅ в backend; ❌ в платформе нет сквозного трейса | |
| **Стоимость** | CapEx без переменных платежей за токены | ~$42,5k за 3 года. ⚠ **цена запроса зависит от утилизации в 20 раз** — она не измерена | [TCO](economics/tco.md) |
| **Сопровождаемость** | Docs-as-Code, ADR в Git, пиннинг версий | ✅ 27 ADR; IaC на OpenTofu, GitOps через ArgoCD | [operations](../../zubriq-platform/docs/operations.md) |
| **Портируемость** | open-weight модель, OpenAI-совместимый API | ✅ смена модели — правка каталога шлюза, а не кода продукта | [ADR-0019](adr/0019-shlyuz-modeley-kak-centr-platformy.md) |
| **Изоляция окружений** | тест, стейдж и прод не пересекаются по данным | ⚠ у Postgres — по конвенции баз; у одиночного Neo4j — **дисциплиной**, и она уже подводила | [adr-audit](adr-audit.md#3-спроектировано-но-в-платформе-не-реализовано) |

## Что в требованиях сознательно отсутствует

- **Целевой профиль нагрузки** (RPS, длина контекста, размер базы). Без него NFR по throughput остаётся ⚠, и это честнее, чем придуманное число.
- **RPO/RTO.** Бэкапы есть, восстановимость не проверялась; порядок подъёма площадки после полного обесточивания нигде не описан.
- **Требования к голосу.** В прежней редакции был целый раздел; в новом продукте голоса нет, и [ADR-0010](adr/0010-voice-stack.md) переведён в «спроектировано, не реализовано».
