# Изолированный A/B якоря статьи на корпусе кодексов РБ

> Прогон 12.09.2026. Скрипт — [`ab-anchor.py`](ab-anchor.py), корпус `zubriq-legal-corpus` (25 кодексов, 12 644 куска), эталон — `dify/kb/codes/golden.jsonl` (61 вопрос).

## Зачем

В пилоте платформы 01.08.2026 разрыв **67 % → 89 % hit@1** объяснили нарезкой с заголовком «Кодекс — Статья N» в каждом куске. Но сравнивали там **две системы**, у которых одновременно различались размер куска, нарезчик и реализация hybrid+rerank. Изолированного замера якоря не делал никто — ни автор пилота, ни я, когда переносил его вывод в свой проект как факт.

Здесь двигается **ровно одна переменная**: есть ли в теле куска заголовок. Нарезка, модели, кандидаты, реранк, эталон — общие.

## Протокол

Взят из `pilot_vectors/eval.py` без изменений: вопрос → `bge-m3` → top-24 кандидатов → `bge-reranker-v2-m3` → top-6 → номер статьи из поля `name` → hit@k против эталона. Нарезка — дословно из `pilot_vectors/chunk.py` (TARGET 1500, HARD_MAX 2000).

**Деталь, без которой замер был бы фиктивным:** поле `name` в обоих вариантах одинаково и в тело безъякорного варианта **не входит**. Метрика читает номер статьи из `name`, а поиск идёт по телу — иначе якорь просочился бы в обе ветки и разница обнулилась бы искусственно.

## Результат

| Тело куска | hit@1 | hit@3 | hit@6 |
|---|---:|---:|---:|
| **Полный якорь** «КоАП — Статья 339. Хулиганство» (как в проде) | **90,2 %** | 95,1 % | 98,4 % |
| Только **название** статьи, без адреса | **90,2 %** | 93,4 % | 95,1 % |
| Только **адрес** «КоАП — Статья 339», без названия | 75,4 % | 88,5 % | 96,7 % |
| **Без якоря** | 73,8 % | 86,9 % | 95,1 % |

Разложение вклада в hit@1 относительно базиса «без якоря»:

| Составляющая | Вклад |
|---|---:|
| только адрес | **+1,6 п.п.** |
| только название | **+16,4 п.п.** |
| адрес + название | +16,4 п.п. |

## Выводы

**1. Интерпретация автора пилота подтвердилась по существу: +16,4 из заявленных 22 п.п. — действительно якорь.** Воспроизведение протокола дало 90,2 % против 89 % в пилоте, расхождение в один вопрос. Остаток (≈6 п.п.) приходится на размер куска и родной retrieval Dify; разделить это можно только прогоном на самом Dify.

**2. Работает не адрес, а название статьи.** Адрес стоит 1,6 п.п. — ровно те два вопроса из 61, которые статью называют («Что говорит статья 121?», «Что говорит статья 205?»). Название даёт все 16,4 и полностью заменяет полный якорь.

Механизм виден в списке сломавшихся. Без якоря ломаются 12 вопросов, адресных среди них два; остальные десять — смысловые:

```
ждали 164  получили 166,164,164   Что такое банковская гарантия?
ждали 27   получили 108,27,83     Со скольки лет наступает уголовная ответственность?
ждали 205  получили 294,205,11.1  Что такое кража как форма хищения?
ждали 19.1 получили 339,339-1,153 Что грозит за мелкое хулиганство?
ждали 155  получили 161,170,181   Сколько дней основного трудового отпуска положено работнику?
```

«Статья 164. Банковская гарантия» — это **написанная человеком тематическая метка**, часто дословно совпадающая с формулировкой вопроса. Текст самой нормы слов «банковская гарантия» рядом может не содержать вовсе: норма описывает механизм, а не называет его.

**3. Адрес всё же нужен — но на глубине, а не в первой позиции.** При hit@1 90,2 % у обоих вариантов, на hit@6 полный якорь даёт 98,4 % против 95,1 % у одного названия. Название выносит правильную статью наверх; адрес удерживает её в выдаче, когда наверх её не вынесло.

**4. Почему на нашем демо-корпусе эффекта не было.** В четырёх ЛПА заголовок раздела (`## 3. Возмещение расходов`) **уже находился внутри текста куска** — отсутствовал только код документа. Мы добавили код и получили эффект только на адресных вопросах, то есть **ровно +1,6-режим этой таблицы**. Никакого противоречия между замерами нет: мы мерили добавление адреса к уже имеющемуся названию.

## Следствие для ingestion НПА — и это риск, а не план

Если сила якоря в человеческом названии, то **эффект зависит от корпуса, а не от приёма**. У кодексов название есть у каждой статьи и оно тематическое. У НПА название есть у акта, а у пунктов внутри — далеко не всегда: «3.1. …» сплошь и рядом идёт без заголовка.

Это не гипотеза, которую предстоит проверять: **её цена уже измерена здесь**. Корпус без человеческих названий на уровне куска — это строка «только адрес», то есть **+1,6 п.п., а не +16**. Закладываться на +16 при переносе на НПА нельзя, пока не проверена доля пунктов с собственными заголовками.

Практический вывод для нарезчика НПА: если у пункта нет своего названия, **наследовать ближайший вышестоящий заголовок** (раздел, глава, название акта) — он тоже написан человеком и тоже тематический. Проверяется тем же прогоном.

## Воспроизведение

```bash
export SUFLER_RERANK_URL=...      # Vault: secret/zubriq-console/env → EMBEDDINGS_URL
export SUFLER_RERANK_API_KEY=...  #                                  → EMBEDDINGS_API_KEY
export SP=<каталог с корпусом и кэшем эмбеддингов>
python docs/eval/ab-anchor.py
```

Эмбеддинги кэшируются в `$SP/emb_*.npy` — повторный прогон считает только метрику. Четыре варианта по 12 644 куска: около 12 минут на батчах по 32 последовательно (без параллелизма — сервис обслуживает продуктивный трафик).
