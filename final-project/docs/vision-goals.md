# Vision & Goals

## Vision
Дать организации **безопасного корпоративного AI-ассистента**, работающего **полностью в контуре** (on-prem / air-gapped), без обращения к внешним LLM-API. Платформа закрывает два сценария поверх **одного self-hosted LLM**:
- **персональный** — личный ассистент и агент для сотрудника (Open WebUI);
- **совместный** — поиск по общим базам знаний компании (Confluence/Jira/SharePoint) с учётом прав доступа (Onyx).

Контекст: организация в **Республике Беларусь** под санкциями → облачные LLM юридически и практически недоступны; данные содержат ПДн и коммерческую тайну (**Закон РБ № 99-З**) → не должны покидать периметр.

## Цели
1. **Персональный ассистент** с агентными возможностями (ReAct / Plan-and-Execute, инструменты, RAG).
2. **Совместный поиск** по корпоративным БЗ с **permission-aware** выдачей (пользователь видит только разрешённое).
3. **Один общий LLM** (open-weight, self-hosted) на обе плоскости — предсказуемый TCO, без лицензионных платежей.
4. **Стандартный слой интеграции** с внутренними системами через **MCP** (написал инструмент один раз — доступен обеим плоскостям).
5. **Полный data-residency**: всё в контуре, нулевой egress к внешним LLM.
6. **Безопасность и соответствие**: guardrails (PII / prompt-injection / toxicity), RBAC, аудит (№ 99-З).
7. **Наблюдаемость и управляемость**: трейсинг запросов, метрики токенов/латенси, документация как код (ADR + диаграммы в Git).

## Не-цели (out of scope)
- **Любой вызов внешних LLM-API** (OpenAI/Anthropic/Azure) — запрещён by design.
- **Обучение собственной foundation-модели** — используем open-weight + RAG (дообучение под факты не нужно).
- **Мульти-облако / мульти-регион** — целевой деплой on-prem bare-metal.
- **Разработка кастомного чат-UI и кастомных коннекторов с нуля** — берём готовые (Open WebUI, Onyx).
- **Гибридный роутинг «локально/облако»** — нарушает air-gapped.

## Стейкхолдеры
| Стейкхолдер | Интерес |
|---|---|
| Сотрудник | Быстрый личный ассистент, экономия времени |
| Команды / коллеги | Поиск по общим знаниям, единая точка правды |
| Администратор / DevOps | Управляемость, RBAC, обновления, мониторинг |
| Служба ИБ | Контур, № 99-З, аудит, отсутствие утечек |
| Менеджмент | Предсказуемый TCO (CapEx), отдача от инвестиции в GPU |

## Метрики успеха
- **Сокращение времени на поиск ответа** (baseline → цель, по аналогии с кейсом урока 08: 5+ мин → ≤ 30 сек).
- **Adoption**: доля активных пользователей / запросов в неделю.
- **Качество**: faithfulness и context precision (RAGAS) выше порога на golden set.
- **Latency p95** ответа в пределах NFR (см. [requirements](requirements.md)).
- **Безопасность**: 0 инцидентов egress данных за пределы контура.
- **Экономика**: TCO в рамках утверждённого CapEx (2× H100 NVL + сопровождение).

## Ограничения (constraints)
- **Air-gapped / on-prem**, без внешних API ([ADR-0001](adr/0001-on-premise-self-hosted-llm.md)).
- **Юрисдикция РБ**: Закон № 99-З; санкции (нет доступа к зарубежным SaaS).
- **Железо фиксировано**: Lenovo SR675 V3, **2× H100 NVL 94 GB** ([ADR-0006](adr/0006-kvantovanie-i-sizing-gpu.md)).
- **Команда**: ML-компетенции начальные → ставка на готовые open-source продукты и большие сообщества.
