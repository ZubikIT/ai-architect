# MVP — «Суфлёр»: копайлот оператора КЦ + ассистент по ЛПА (+ голос)

## Выбор темы
**Тема B — Advanced RAG** (основная), с элементами **A — Cognitive** (Суфлёр-копайлот) и расширением в голосовую модальность.

**Почему B:** ядро MVP — ответы по **внутренней БЗ и ЛПА** (локальные правовые/нормативные акты) с **hybrid search + reranking** (урок 06). Это ровно Advanced RAG. Преемственность: развитие кейса **Суфлёр БФТ** (уроки 02/05) — теперь не исходящий обзвон, а **inbound-копайлот**.

## Кейс и 3 этапа
| Этап | Что | Тема | Scope MVP |
|---|---|---|---|
| **1. База знаний** | Сбор и индексация ЛПА + внутренней БЗ (Confluence/Jira/SharePoint через Onyx) | B (ingestion) | ✅ в MVP |
| **2. Суфлёр (текст)** | Бот подсказывает **оператору КЦ** ответ на вопрос клиента; **тот же бот** отвечает **сотрудникам** по ЛПА/БЗ | B + A | ✅ в MVP (минимальный пример) |
| **3. Голос** | То, что на этапе 2 было текстом, ассистент **отвечает голосом** (STT+TTS) | модальность | 🟡 расширение (ADR-0010) |

**Кодируемый минимум MVP = этап 1 + этап 2 (текст).** Этап 3 (голос) — спроектирован, реализуется как расширение.

## Как ложится на принятый стек (ADR)
Ничего нового для этапов 1–2 изобретать не нужно — переиспользуем:
- **LLM:** Qwen3.6-27B на vLLM/FP8 ([ADR-0002/0003/0006](adr/)).
- **RAG:** Qdrant + hybrid (dense+BM25) + rerank ([ADR-0004](adr/0004-vector-db.md), урок 06).
- **Коннекторы БЗ:** Onyx (Confluence/Jira/SharePoint, permission-aware) ([ADR-0008](adr/0008-knowledge-base-connectors.md)).
- **Оркестрация:** LangGraph (когда нужен агентный путь/инструменты) ([ADR-0005](adr/0005-orchestration.md)).
- **UI:** Open WebUI — окно сотрудника/оператора ([ADR-0007](adr/0007-chat-interface.md)); интеграции через MCP ([ADR-0009](adr/0009-mcp-integration-layer.md)).
- **Guardrails:** PII/инъекции/«не знаю» (анти-галлюцинации) — критично для ЛПА.
- **Новое (этап 3):** self-hosted STT/TTS ([ADR-0010](adr/0010-voice-stack.md)).

## Этап 1 — формирование базы знаний
1. **Источники:** ЛПА (PDF/DOCX из SharePoint), статьи Confluence, тикеты Jira.
2. **Ingestion (Onyx):** инкрементальная синхронизация, **наследование прав** (permission-aware).
3. **Chunking:** recursive по структуре документа (разделы ЛПА) — сохранить ссылки на пункт/документ для цитирования.
4. **Embedding + индекс:** в Qdrant (dense) + sparse (BM25) для hybrid.
5. **DoD этапа 1:** ЛПА и БЗ проиндексированы; поиск возвращает релевантные пункты с источником; права соблюдены.

## Этап 2 — Суфлёр (текст), два режима
Один RAG-движок, два входа:

**A. Копайлот оператора КЦ.** Оператор слышит вопрос клиента → вводит/вставляет его → Суфлёр мгновенно предлагает **черновик ответа + ссылку на пункт ЛПА**. Оператор решает, что сказать (human-in-the-loop по умолчанию — бот не говорит клиенту напрямую).

**B. Ассистент сотрудника.** Сотрудник спрашивает в Open WebUI по ЛПА/внутренней БЗ → Суфлёр отвечает с цитатами.

Поток (см. также [Sequence](../diagrams/sequence-er.md)):
```
вопрос → guardrails(in) → hybrid retrieve (Qdrant, RBAC-фильтр) → rerank (cross-encoder)
       → промпт «отвечай ТОЛЬКО по контексту, иначе „не знаю“» → Qwen3.6 (vLLM)
       → guardrails(out: PII, «не знаю») → ответ + цитаты [ЛПА §, ссылка]
```

**DoD этапа 2:**
- Ответ строго по контексту, с **цитированием источника**; при отсутствии — «не знаю, уточните у …».
- Латенси копайлота — короткая (оператор не ждёт); faithfulness выше порога (RAGAS) на golden set вопросов по ЛПА.
- RBAC: сотрудник не получает документы вне своих прав.

### Минимальный пример (псевдокод ядра RAG)
```python
# 1. Ingestion (этап 1) — упрощённо
chunks = chunk_documents(load_lpa_docs())          # recursive split, с метаданными (doc, section, acl)
qdrant.upsert(embed_dense(chunks), sparse=bm25(chunks), payload=meta)

# 2. Retrieve + rerank (этап 2)
def answer(question, user):
    guard_in(question)                              # PII / prompt-injection
    cands = qdrant.hybrid_search(                   # dense + BM25 (RRF)
        question, top_k=20,
        acl_filter=user.roles)                      # permission-aware (№99-З)
    top = cross_encoder_rerank(question, cands)[:5] # урок 06
    prompt = build_prompt(question, context=top)    # "Отвечай ТОЛЬКО по контексту, иначе 'не знаю'"
    draft = vllm_chat(prompt)                        # Qwen3.6 через OpenAI API
    return guard_out(draft) + citations(top)         # PII-маска + ссылки на ЛПА §
```
Развёртывание: ядро как сервис (FastAPI) → подключается к Open WebUI (OpenAI-совместимый) и/или как MCP-инструмент для агента.

## Этап 3 — голос (расширение)
То же ядро, добавляется модальность:
- **STT** (распознавание речи) → текст вопроса → этап 2 → ответ.
- **TTS** (синтез) → ответ озвучивается.
- **Ассистент сотрудника:** голосовой режим — через voice-call Open WebUI / Conduit + self-hosted STT/TTS.
- **Копайлот оператора:** опционально стриминговый STT по реплике клиента (как в исходном Суфлёр БФТ — SIP/Asterisk), бот суфлирует оператору, **клиенту не говорит**.
- Стек STT/TTS — self-hosted (air-gapped, РБ): см. [ADR-0010](adr/0010-voice-stack.md).
- **DoD этапа 3:** голосовой ответ на типовой вопрос по ЛПА; задержка распознавание→ответ→синтез в пределах NFR.

## Метрики MVP
- **Качество:** faithfulness / context precision (RAGAS) на golden set по ЛПА.
- **Скорость:** время до подсказки оператору; TTFT; (этап 3) end-to-end voice latency.
- **Польза:** % принятых операторами подсказок; сокращение времени ответа клиенту.
- **Безопасность:** 0 ответов вне прав пользователя; 0 утечек ПДн в ответах.
