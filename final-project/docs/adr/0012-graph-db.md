# ADR-0012. Graph Database — Neo4j Community (vs ArangoDB, NebulaGraph, Memgraph, граф внутри Qdrant/PostgreSQL)

## Контекст

Уточнённое ТЗ финального проекта (занятие [32](../../sessions/32-vybor-temy.md)) делает **GraphRAG обязательным**: «нет реализации GraphRAG — простой векторный поиск не принимается» (критерий статуса «Не принято»). Нужен слой хранения графа знаний поверх уже выбранного вектора ([ADR-0004](0004-vector-db.md) Qdrant).

Силы давления:

- **Air-gapped / № 99-З ([ADR-0001](0001-on-premise-self-hosted-llm.md)):** строго self-hosted, офлайн-установка, никаких managed-сервисов (Neo4j Aura, ArangoGraph исключены по определению).
- **Домен — ЛПА и корпоративные регламенты:** плотная сеть перекрёстных ссылок между пунктами и редакциями («п. 4.2 применяется с учётом п. 7.1», «настоящий приказ отменяет приказ № …»). Именно эти рёбра плоский вектор теряет — это и есть «потеря контекста» из формулировки цели ТЗ.
- **Демонстрируемость:** ТЗ требует в видео-демо «визуализацию построенного графа в браузере Neo4j/Falkor/Nebula» — БД обязана иметь **встроенный браузер графа**, показываемый без написания фронтенда.
- **Security-by-Design:** ACL на уровне **узлов/чанков** — нужна возможность хранить метку доступа на узле и фильтровать её **в самом запросе обхода**, а не после (иначе утечка через связи).
- **Эксплуатация:** команда с начальным MLOps → минимум движущихся частей, один контейнер в `docker-compose`, предсказуемый рестор.
- **Масштаб:** корпус ЛПА и внутренней БЗ — порядок 10⁵–10⁶ узлов и 10⁶–10⁷ рёбер. Это **малый граф**: распределённость не нужна, всё помещается в память одной ноды.
- **Материалы ТЗ:** в раздаточных материалах курса даны docker-образы **Neo4j** и Qdrant — то есть эталонный путь проверяющего совпадает с Neo4j.

## Рассмотренные варианты

1. **Neo4j Community 5.x** _(выбран)_
   - **Хорошо:** де-факто стандарт property-graph, **Cypher** (самый распространённый язык обхода → максимум примеров и LLM-знаний о нём, что важно для text2Cypher); **Neo4j Browser из коробки** — закрывает требование ТЗ к видео-демо без единой строки фронтенда; **APOC** и **GDS (Graph Data Science)** доступны в Community — дают community detection (Leiden/Louvain) как upgrade-path к «глобальным» вопросам; нативный **векторный индекс** с 5.11 — резервный путь, если понадобится схлопнуть два хранилища в одно; один контейнер, офлайн-образ, тривиальный `dump`/`load`; официальные драйверы Python и интеграции LangChain/LlamaIndex — минимум клея.
   - **Плохо:** **Community = GPLv3** (для внутреннего корпоративного использования приемлемо, но накладывает ограничения при возможной дистрибуции продукта); **нет ролевой модели БД** (fine-grained RBAC, multi-database, online backup, кластер — только Enterprise) → **ACL придётся реализовать на уровне приложения и свойств узла**; single-instance → нет HA средствами БД.
2. **ArangoDB Community** (multi-model: документы + граф + вектор в одном движке)
   - **Хорошо:** один движок вместо двух (граф + вектор), AQL покрывает оба доступа, Apache 2.0-дружелюбная лицензия для community-редакции.
   - **Плохо:** меньше экосистемы и примеров под GraphRAG; встроенный вектор слабее Qdrant по payload-фильтрации (а фильтрация — основа нашего RBAC, [ADR-0004](0004-vector-db.md)); визуализация беднее Neo4j Browser; менять уже принятый Qdrant ради «одного движка» — переделка без выигрыша в сроке защиты.
3. **NebulaGraph**
   - **Хорошо:** распределённый, рассчитан на десятки миллиардов рёбер; упомянут в ТЗ как допустимый браузер графа.
   - **Плохо:** **ops-overkill** — meta/graph/storage-сервисы отдельными компонентами; наш граф на 3–4 порядка меньше порога, где это окупается; для команды с начальным MLOps — лишний риск в air-gapped.
4. **Memgraph / FalkorDB** (in-memory, Cypher-совместимые)
   - **Хорошо:** очень быстрый обход, Cypher-совместимость, лёгкий контейнер; FalkorDB популярен именно в GraphRAG-стеках.
   - **Плохо:** in-memory-профиль требует аккуратной работы с durability (а граф у нас пишется пачками из ingestion); экосистема и материалы тоньше; проверяющий будет смотреть демо на Neo4j-подобном браузере — отклонение от эталонного пути ТЗ без технической необходимости.
5. **Не заводить графовую БД: рёбра в payload Qdrant / таблицы PostgreSQL**
   - **Хорошо:** ноль новых компонентов.
   - **Плохо:** обход на 2+ хопа превращается в рекурсивные SQL/серии запросов; нет визуализации графа (**прямое требование видео-демо**); и главное — **формально это не GraphRAG** → риск статуса «Не принято». **Rejected.**

## Решение

Берём **Neo4j Community 5.x** как graph store в связке с **Qdrant** как vector store (гибрид, стратегия retrieval — [ADR-0013](0013-graphrag-strategiya.md)).

Что перевесило: единственный кандидат, закрывающий одновременно (а) требование ТЗ к **визуализации графа в демо** из коробки, (б) Cypher как язык с максимальным покрытием в знаниях LLM (нужно для шаблонного text2Cypher), (в) GDS/APOC в Community как путь к community-summarization без смены БД, (г) один контейнер в `docker-compose` для air-gapped, (д) совпадение с эталонными материалами курса.

**Rejected:** NebulaGraph (ops-overkill на нашем масштабе), «граф без графовой БД» (не удовлетворяет критерию GraphRAG и требованию визуализации). **Отклонены без ошибки:** ArangoDB (переделка уже принятого вектора без выигрыша), Memgraph/FalkorDB (тоньше экосистема при равной функции).

**Статус `proposed`:** перед `accepted` — прогнать ingestion реального корпуса ЛПА и замерить (1) время построения графа, (2) latency обхода 2 хопа с ACL-фильтром под нагрузкой из [ДЗ-24](../../../24-high-load-low-latency/Zubik_DZ-24_highload-realtime.md), (3) объём БД на диске. Если обход с фильтром не уложится в бюджет latency — рассматривать Memgraph (`superseded by`).

## Последствия

- **Положительные:**
  - Критерий «Не принято» по GraphRAG закрывается архитектурно, а не обещанием.
  - Neo4j Browser даёт готовый кадр для видео-демо (граф + ACL-фильтр вживую).
  - GDS в Community оставляет апгрейд к community detection без миграции данных.
  - Cypher-запросы читаемы в защите — рецензенту видно, что обход реальный, а не декоративный.
- **Отрицательные / риски:**
  - **GPLv3** — фиксируем как ограничение на дистрибуцию; для внутреннего контура банка приемлемо, при коммерциализации потребуется Enterprise-лицензия или миграция (вариант 4 как запасной).
  - **Нет RBAC средствами БД** → доступ реализуем свойством узла + обязательным предикатом в каждом запросе. Риск «забыли фильтр» — снимается тем, что **все запросы идут через единый слой репозитория**, а не из кода агентов, плюс негативным тестом «User B» в CI (планируемый ADR-0018).
  - **Single instance, нет online backup** → HA средствами БД отсутствует. Митигация архитектурная: **граф — производный артефакт**, source of truth — исходные документы и Qdrant-чанки; полная переиндексация восстанавливает граф, плюс регламент `neo4j-admin dump` по расписанию в контуре.
  - **Два хранилища** (Qdrant + Neo4j) → риск рассинхронизации. Митигация: сквозной `chunk_id` как ключ в обеих БД и идемпотентный ingestion (upsert по хешу содержимого).
- **Что придётся изменить дальше:**
  - Обновить **C4 L2 / Deployment / ER** — добавить Neo4j в Data Plane, схему графа в ER.
  - Добавить Neo4j в `/infra/docker-compose.yml` (с `NEO4J_AUTH` из Vault, без дефолтного пароля).
  - Зафиксировать онтологию и индексы (constraints на `chunk_id`, индекс по `acl_roles`) — [ADR-0013](0013-graphrag-strategiya.md).

## Compliance & Ethics _(AI-специфичный раздел, урок 08)_

- **№ 99-З / air-gapped:** Neo4j self-hosted в контуре, офлайн-образ, никаких телеметрических обращений (отключить `dbms.usage_report`); дампы не покидают периметр.
- **ПДн в графе:** узлы-сущности могут содержать ФИО из ЛПА и обращений → PII-санитизация **на ingestion**, до записи в граф (Presidio, [урок 14](../../../14-security-by-design/14-security-by-design.md)); право на забвение реализуется удалением узла и его рёбер вместе с чанками Qdrant по общему `chunk_id`.
- **Прозрачность:** каждый узел хранит провенанс (документ-источник, версия, дата индексации) — ответ агента цитирует пункт ЛПА, а не «знание модели»; это же защищает от RAG-poisoning (отравленный узел виден по источнику).
- **Доступ:** ACL-метка на узле — часть модели данных, а не логики приложения; невозможность получить чужой документ проверяется автотестом, а не декларацией.
