# ADR-0007. Чат-интерфейс — Open WebUI

## Контекст
Нужен пользовательский фронт к self-hosted LLM (ADR-0001) и движку vLLM (ADR-0003). Силы давления:

- **Air-gapped (ADR-0001):** UI должен работать **полностью офлайн**, без внешних коннекторов и телеметрии.
- **Интеграция:** vLLM отдаёт **OpenAI-совместимый** эндпоинт → хочется фронт, который подключается без «клея».
- **Энтерпрайз:** нужны **SSO (OIDC)** под корпоративный IdP и **RBAC** (кто к чему имеет доступ) — требование № 99-З по учёту доступа к ПДн.
- **Расширяемость:** место для **guardrails** (PII, prompt injection, toxicity) и кастомной логики в потоке запроса/ответа (это же тема Блока 3 «Security»).
- **Мобайл:** нужен мобильный доступ.
- **Команда:** ML начальный → предпочтителен готовый продукт, а не кастом-разработка UI.

## Рассмотренные варианты
1. **Open WebUI** _(выбран)_
   - **Хорошо:** self-host/офлайн; коннектор к OpenAI-совместимому API → подключается к vLLM без клея; встроенные **OIDC SSO + RBAC**; **Pipelines** (Python-фильтры в потоке — идеальны под guardrails/логирование/PII); встроенный RAG; активное сообщество; мобильный клиент **Conduit**.
   - **Плохо:** быстро меняется (нужен version-pinning); user-facing web-tier = поверхность атаки (в DMZ, security-review).
2. **LibreChat**
   - **Хорошо:** зрелый self-host мультимодельный чат, OIDC-аутентификация.
   - **Плохо:** экосистема плагинов/guardrails слабее Pipelines; меньше «из коробки» под наш сценарий.
3. **HuggingFace chat-ui**
   - **Хорошо:** официальный, лёгкий, self-host.
   - **Плохо:** SSO/RBAC и плагины — не из коробки, придётся допиливать.
4. **Кастомный UI** (Chainlit / React + FastAPI)
   - **Хорошо:** максимум контроля.
   - **Плохо:** высокий объём работы — переизобретаем auth/RBAC/RAG/мобайл; не оправдано для команды с начальным ML.
5. **AnythingLLM**
   - **Хорошо:** простой workspace-RAG UI.
   - **Плохо:** менее гибкие SSO/RBAC и расширения, чем Pipelines.

## Решение
Берём **Open WebUI** как чат-интерфейс. Что перевесило: офлайн-работа под air-gapped, нулевой «клей» к vLLM (OpenAI API), встроенные **SSO (OIDC) + RBAC**, **Pipelines** как штатное место для guardrails (синергия с Блоком 3 Security), готовый мобильный клиент **Conduit**. Кастом и более «лёгкие» UI — **Rejected** (избыточная разработка / нет нужных энтерпрайз-функций).

Статус **accepted** (решение принято командой); конкретная схема SSO (Keycloak/AD FS) и набор Pipelines уточняются на этапе реализации.

## Последствия
- **Положительные:**
  - Быстрый запуск UI без разработки; SSO/RBAC и аудит доступа из коробки (№ 99-З).
  - **Pipelines** = единая точка для Input/Output Guardrails (PII, prompt injection, toxicity) → закрывает Блок 3 Security.
  - Мобильный доступ через **Conduit** (нативный iOS/Android, поддерживает SSO/LDAP/JWT) без отдельной разработки.
- **Отрицательные / риски:**
  - User-facing web-tier — поверхность атаки: размещение в **DMZ**, security-review, секреты в Vault, TLS.
  - Open WebUI быстро развивается → **пинить версии**, регламент обновлений, проверять changelog на ломающие изменения.
  - **Conduit — сторонний** open-source клиент (НЕ официальный проект Open WebUI): зависимость от внешнего мейнтейнера → проверять обновления/безопасность, пинить версию, рассмотреть форк/self-build при критичности.
  - Нужно отключить внешние коннекторы (web search) и телеметрию для air-gapped.
- **Что придётся изменить дальше:**
  - Спроектировать Pipelines под guardrails (PII-фильтр, prompt-injection) — Блок 3.
  - Завести ADR на схему SSO/IdP при необходимости; отразить web-tier в Deployment-диаграмме (DMZ) и RBAC в ER-диаграмме.

## Compliance & Ethics _(AI-специфичный раздел, урок 08)_
- **Air-gapped:** отключить web search, внешние коннекторы и телеметрию; единственный upstream — внутренний vLLM-эндпоинт.
- **№ 99-З:** SSO + RBAC дают учёт доступа к ПДн; логи доступа — в контуре.
- **Guardrails:** PII-маскирование и фильтрация токсичности/инъекций реализуются в Pipelines (перед/после модели), а также дисклеймер «я бот».
