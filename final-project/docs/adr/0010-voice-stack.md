# ADR-0010. Голосовой стек — self-hosted STT/TTS

## Контекст
Этап 3 MVP ([mvp.md](../mvp.md)) — голосовой Суфлёр: распознавание речи (STT) + синтез (TTS) поверх текстового RAG-ядра. Силы давления:

- **Air-gapped / РБ / № 99-З (ADR-0001):** облачные речевые сервисы (Yandex SpeechKit, SaluteSpeech) **недоступны** (санкции) и нарушают контур. **Голос — это ПДн/биометрия** → аудио не покидает периметр.
- **Русский язык:** нужна сильная RU-модель STT и естественный RU-голос TTS.
- **Железо:** есть 2× H100 NVL — STT можно гонять на GPU; TTS — лёгкий (CPU/GPU).
- **Латенси:** копайлот оператора и голосовой ассистент требуют низкой end-to-end задержки (стриминг).
- **Два сценария:** (а) ассистент сотрудника — микрофон/voice-call в Open WebUI / Conduit; (б) копайлот оператора КЦ — стриминговый STT по реплике клиента (телефония SIP/Asterisk, как в Суфлёр БФТ), бот суфлирует оператору, клиенту не говорит.

## Рассмотренные варианты
**STT:**
1. **faster-whisper (Whisper large-v3, CTranslate2)** _(выбран, baseline)_ — сильный RU, self-host, эффективен на GPU; стриминг через whisper-streaming/WhisperLive. Минус: large-v3 требует GPU-памяти (на H100 не проблема).
2. **GigaAM-v3 (Sber)** _(сильный RU-кандидат)_ — ASR, заточенный под русский; в реальном деплое zubriq.by уже намечен как локальная замена облачного STT для прода МТБанка. Проверить на PoC против faster-whisper по RU-точности и латенси.
3. Vosk — лёгкий, офлайн, RU, но точность ниже.
4. NVIDIA Parakeet/Canary — быстрый, но RU-поддержка слабее.

**TTS:**
1. **Silero TTS** _(выбран, baseline)_ — RU-native, быстрый, лёгкий (CPU/GPU), free; хорошее качество для делового голоса.
2. XTTS-v2 (Coqui) — мультиязык + клонирование голоса, качество выше, но тяжелее (GPU) — _как апгрейд при требовании брендового голоса_.
3. Piper — очень быстрый, есть RU-голоса; запас по латенси.

**Облачные (SpeechKit/SaluteSpeech)** — **Rejected:** cloud, санкции, не air-gapped, голосовые ПДн наружу.

## Решение
Self-hosted: **STT — faster-whisper (Whisper large-v3) или GigaAM-v3** (выбор по RU-eval на PoC) на GPU; **TTS — Silero** (baseline), XTTS-v2 — апгрейд при необходимости брендового/клонированного голоса. Всё в контуре.

- **Ассистент сотрудника:** STT/TTS подключаются к **voice-режиму Open WebUI** (и Conduit) — минимум интеграции.
- **Копайлот оператора:** стриминговый STT по аудио клиента (SIP/Asterisk-шлюз из дизайна Суфлёр БФТ) → текст → RAG-ядро → подсказка оператору (текст/голос в ухо); **клиенту бот не отвечает напрямую** (HITL).

**Статус `proposed`:** подтвердить на PoC RU-точность STT и качество/латенси TTS на целевом железе; решить Silero vs XTTS-v2 по требованию к голосу.

## Последствия
- **Положительные:**
  - Полностью в контуре (air-gapped, № 99-З по голосовым ПДн); без облака/санкционных рисков.
  - Whisper large-v3 — сильный RU; Silero — лёгкий, не конкурирует за VRAM с LLM.
  - Переиспользование SIP/Asterisk-дизайна из Суфлёр БФТ для телефонии.
- **Отрицательные / риски:**
  - Стриминговый STT с низкой задержкой — нетривиален (буферизация, эндпоинтинг); PoC обязателен.
  - Доп. GPU-нагрузка от STT → учесть в sizing (ADR-0006); при пике — вторая H100/очередь.
  - Качество TTS Silero может не устроить под «брендовый» голос → запасной XTTS-v2.
- **Что придётся изменить дальше:**
  - Дополнить Deployment-диаграмму голосовым шлюзом (SIP/Asterisk) и STT/TTS-сервисами.
  - Политику хранения/удаления аудио (ретеншн, № 99-З) и согласие на запись.

## Compliance & Ethics _(AI-специфичный раздел, урок 08)_
- **Голос = ПДн/биометрия (№ 99-З):** аудио и транскрипты — только в контуре; ретеншн с TTL; согласие на запись/обработку.
- **Air-gapped:** никаких облачных речевых API; STT/TTS self-hosted.
- **HITL:** в копайлоте оператора бот не говорит клиенту — финальное слово за человеком (снижает риск ошибочного/галлюцинированного ответа голосом).
