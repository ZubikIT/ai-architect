# ADR-0005. Orchestration — LangGraph (vs LlamaIndex Workflows)

## Контекст
Ядро — агентная система (уроки 07/08), а не линейный RAG-pipeline. Нужен фреймворк оркестрации. Силы давления:

- **Бриф:** «Линейные цепочки **запрещены** — нужна **stateful**-оркестрация»; кандидаты — LangGraph или LlamaIndex Workflows.
- **Сценарий (ДЗ-07):** мультиагентность с делегированием (Менеджер → Поисковик/Аналитик/Бронировщик), циклы ReAct / Plan-and-Execute, **human-in-the-loop** на подтверждениях.
- **Надёжность:** нужны **checkpointing / персистентность состояния** (возобновление, аудит шагов), лимиты циклов и бюджета (safety-net из урока 07).
- **Совместимость:** tool-calling модели (ADR-0002 Qwen3.6), vLLM через OpenAI API (ADR-0003), RAG поверх Qdrant (ADR-0004).
- **Air-gapped:** это Python-библиотека, работает офлайн — ограничение ADR-0001 не мешает.
- **Команда:** начальный ML → ценится большое сообщество и примеры.

## Рассмотренные варианты
1. **LangGraph** _(выбран)_
   - **Хорошо:** граф состояний/узлов — точно ложится на stateful мультиагент с циклами и ветвлением; встроенные **checkpointing/persistence** и **human-in-the-loop**; явный контроль над состоянием и переходами; крупнейшая экосистема (LangChain), много примеров; **бриф называет его первым кандидатом**; естественно ложится на ДЗ-07 (Менеджер→Поисковик).
   - **Плохо:** многословнее для простого RAG; тянет часть экосистемы LangChain.
2. **LlamaIndex Workflows**
   - **Хорошо:** event-driven, лаконичный async; сильные RAG-примитивы из коробки; легче для RAG-центричных пайплайнов.
   - **Плохо:** агентная stateful-оркестрация с циклами/HITL менее «из коробки», чем граф LangGraph; экосистема под мультиагент скромнее.
3. **Кастомный стейт-машина / голый Python**
   - **Хорошо:** ноль зависимостей.
   - **Плохо:** переизобретаем checkpointing, HITL, ретраи; не оправдано для команды с начальным ML.

## Решение
Берём **LangGraph** как фреймворк оркестрации агентов. Что перевесило: граф состояний идеально кладётся на stateful мультиагентный сценарий с циклами и HITL, встроенные checkpointing/persistence, крупнейшее сообщество и прямое указание брифа. **LlamaIndex Workflows** — сильная альтернатива для RAG-центричной части (может использоваться точечно для retrieval-пайплайна), кастом — **Rejected**.

**Статус `proposed`:** подтвердить на прототипе ДЗ-07 (Менеджер делегирует Поисковику) — проверить tool-calling Qwen3.6 через vLLM в графе и persistence. Возможна гибридизация: LangGraph — оркестрация агентов, LlamaIndex — retrieval-слой.

## Последствия
- **Положительные:**
  - Граф + checkpointing → возобновляемость, аудит шагов агента (важно для № 99-З и отладки).
  - HITL из коробки → подтверждения критичных действий (например, перед записью/бронью).
  - Большое сообщество → ниже риск для команды с начальным ML.
- **Отрицательные / риски:**
  - Зависимость от экосистемы LangChain (версии, breaking changes) → пинить версии.
  - Избыточность для простых RAG-запросов → для них допустим короткий путь без полного графа.
- **Что придётся изменить дальше:**
  - Спроектировать граф агентов (узлы, состояние, лимиты циклов/бюджета) на C4 L3 (Agent internals) и Sequence-диаграмме.
  - Выбрать хранилище состояния для checkpointing (Postgres/Redis) в контуре.

## Compliance & Ethics _(AI-специфичный раздел, урок 08)_
- **Safety-net (урок 07):** жёсткие лимиты на число шагов/циклов и бюджет токенов; обрыв «зацикленного» агента.
- **№ 99-З / аудит:** persistence шагов агента и tool-вызовов → прозрачный аудит-трейл в контуре.
- **HITL:** критичные/необратимые действия — только после подтверждения человеком.
