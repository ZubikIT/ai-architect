# ADR-0001. Self-hosted open-weight LLM вместо облачного API (on-premise / air-gapped)

## Контекст
Проектируем ядро корпоративной интеллектуальной системы. Это не «нам нужна LLM», а набор **ограничений**:

- **ТЗ:** система работает **полностью автономно (on-premise / air-gapped)**, без доступа к внешним API (OpenAI / Anthropic).
- **Юрисдикция РБ:** организация в **Республике Беларусь**. Применим **Закон РБ № 99-З «О защите персональных данных»** (регулятор — НЦЗПД); трансграничная передача ПДн ограничена. База знаний — внутренние документы и регламенты с ПДн и коммерческой тайной → данные **не должны покидать контур**.
- **Санкции:** РБ под санкциями → доступ к OpenAI / Anthropic / Azure OpenAI закрыт их же ToS и платёжно — это не «нестабильно», а **юридически и практически недоступно**.
- **Железо:** on-prem сервер **Lenovo ThinkSystem SR675 V3 с 2× NVIDIA H100 NVL 94 GB** (≈188 GB суммарно, NVLink) — фиксированный ресурс в контуре, не облако. Sizing и квантование — [ADR-0006](0006-kvantovanie-i-sizing-gpu.md).
- **Команда:** есть DevOps, ML-компетенции — начальные.

## Рассмотренные варианты
1. **SaaS LLM API** (OpenAI / Anthropic / Azure OpenAI)
   - **Хорошо:** эталонное качество, Time-to-Market < 1 недели, ноль инфраструктуры, OpEx без капзатрат.
   - **Плохо:** данные покидают периметр — **нарушение ТЗ и Закона № 99-З**; не работает в air-gapped; **недоступно из РБ** (санкции/ToS/оплата); vendor lock-in; OpEx растёт с нагрузкой.
2. **Self-hosted open-weight LLM** (Qwen, DeepSeek, T-lite / Saiga) на vLLM/SGLang/TGI
   - **Хорошо:** данные остаются в контуре; полный контроль над инференсом; работает air-gapped; нет лицензионных платежей; есть модели с поддержкой русского; не зависит от санкций.
   - **Плохо:** качество ниже топовых SaaS (риск галлюцинаций на сложных запросах); нужен MLOps и GPU (CapEx — уже закрыт закупкой); ответственность за обновления и безопасность модели — на нас.
3. **Гибрид** (роутинг: простые запросы — локально, сложные — в облако)
   - **Хорошо:** баланс качества и стоимости.
   - **Плохо:** часть данных всё равно уходит наружу → **нарушает air-gapped и № 99-З**, недоступно из РБ, усложняет контроль PII и аудит. Не проходит по ТЗ.

## Решение
Используем **self-hosted open-weight LLM**, развёрнутую внутри изолированного контура; внешние LLM-API **запрещены**. Вариант 1 (SaaS) — **Rejected** (нарушение ТЗ/№99-З + недоступность из РБ), вариант 3 (гибрид) — **Rejected** (нарушает air-gapped).

Конкретная модель, движок инференса и стратегия квантования выносятся в отдельные решения (см. «Связи»), чтобы это фундаментальное ADR оставалось стабильным при их эволюции.

## Последствия
- **Положительные:**
  - Соответствие ТЗ (air-gapped) и Закону № 99-З; данные не покидают контур.
  - Независимость от санкций и зарубежных провайдеров; нет переменных расходов на токены (предсказуемый TCO).
- **Отрицательные / риски:**
  - Качество ответов ниже моделей класса GPT-4 → риск неверных ответов на сложных запросах (митигируется RAG-grounding + guardrails).
  - Нужны компетенции DevOps/MLOps (мониторинг, обновления, безопасность весов).
  - Throughput и длина контекста ограничены доступным железом (2× H100 NVL — см. ADR-0006).
- **Что придётся изменить дальше:**
  - Выбрать модель, движок инференса, стратегию квантования и sizing GPU.
  - Внедрить Input/Output Guardrails (PII, prompt injection, toxicity) и Model Card на выбранную модель.

## Compliance & Ethics _(AI-специфичный раздел, урок 08)_
- **№ 99-З / тайна:** инференс и данные — только в контуре; внешний трафик к LLM-провайдерам заблокирован на сетевом уровне; трансграничная передача ПДн исключена.
- **Скачивание весов:** из доверенного зеркала, доступного из РБ (ModelScope / внутреннее зеркало), офлайн, с проверкой checksum — см. ADR-0002.
- **Галлюцинации:** обязательный RAG-grounding, ответ «не знаю» как валидный, дисклеймер «я бот, могу ошибаться».
- **Bias:** базовая instruction-tuned модель → риск предвзятости; план — eval на golden set (RAGAS) перед релизом.
- **Jailbreak / toxicity:** output-guardrails как постфильтр перед отдачей пользователю.
