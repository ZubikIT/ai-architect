# Платформенный слой

Всё, что не является продуктом, но без чего не работает ни один продукт.

## Шлюз моделей

Единая точка входа ко всем моделям, OpenAI-совместимый API. Отвечает за четыре вещи сразу, и именно совмещение делает его центром платформы:

| Функция | Что конкретно |
|---|---|
| **Ключи** | virtual keys с привязкой к пользователю и организации; выпуск — из консоли |
| **Бюджеты** | лимит на ключ; превышение — отказ на входе, до обращения к модели |
| **Каталог** | список моделей и цен; клиент зовёт по имени, не зная, где модель физически |
| **Учёт** | фактическое потребление в токенах и деньгах — в базу, из неё в счёт |

Клиенту видна только одна сущность: ключ и имя модели. Где модель — на своём боксе или у стороннего вендора — скрыто за каталогом. Это и удобство, и **место, где решается вопрос контура**.

### Каталог моделей

Два плеча, принципиально разных по свойствам:

**Своё.** Имя `zubr` указывает на self-hosted модель — запрос не покидает контур. Отдельно опубликована небольшая VL-модель для разбора изображений.

**Внешнее.** Доступ к нескольким сотням проприетарных моделей через **один upstream-аккаунт агрегатора**: клиент зовёт `<агрегатор>/<вендор>/<модель>`, маршрут задан шаблоном, а не перечислением — новые модели вендоров появляются без правки конфигурации. Стоимость считает встроенная карта цен, платформа начисляет наценку.

Отдельными маршрутами подключены прямые вендорские API — исторически, до появления агрегатора.

> Для [курсового проекта](../../final-project/) пригодно **только первое плечо**: критерий приёмки прямо запрещает облачные API. Это не недостаток платформы, а разные задачи: коммерческий продукт продаёт оба режима, проектируемый контур — только закрытый.

### Собственный инференс

- **Железо:** GPU-бокс, 4 ускорителя NVIDIA Tesla V100 SXM2 по 16 ГБ.
- **Движок:** vLLM, запущен **нативно через systemd, без контейнера** — ради прямого контроля над VRAM и стартовым порядком.
- **Модель:** Qwen3.6-35B-A3B в AWQ-квантовании — MoE, 35 млрд параметров всего при примерно 3 млрд активных на токен. Tensor-parallel по всем четырём картам, окно контекста 64k.
- **Веса** хранятся в объектном хранилище и синхронизируются на бокс при старте сервиса — то есть бокс восстановим без ручного копирования моделей.
- **Предыдущая модель оставлена на диске и в хранилище** как путь отката: возврат — это смена версии в юните.

Ограничение, определяющее весь дизайн инференса: **VRAM эксклюзивна**. На 64 ГБ суммарно не помещаются одновременно основная модель и крупные пилотные, поэтому юниты объявляют взаимное исключение — запуск одного останавливает другой. Отсюда правило эксплуатации: пилот и прод на одном боксе не сосуществуют, и деплой одного во время работы другого запрещён явно.

Выбор MoE-модели с малой активной частью — прямое следствие того же ограничения: при 35 млрд параметров общего размера на токен работают около 3 млрд, что даёт приемлемую скорость на картах поколения V100.

## Идентификация и доступ

Единый вход по OIDC для всех продуктов: отдельная область (realm) платформы, клиенты для чата, консоли и хранилища документов. Группы пользователя кладутся в токен отдельным scope и мэппером — продукты принимают решения о правах по группам, а не по спискам внутри себя.

Учётные записи приходят федерацией из внутреннего каталога; членство в группах кэшируется, и это даёт практическое следствие: **изменение прав вступает в силу не мгновенно**. Отзыв доступа требует либо истечения кэша, либо явного сброса — в эксплуатации это отдельная процедура, а не «поправил группу и готово».

Административная панель консоли отделена от клиентской части доменом и доступна только сотрудникам платформы: проверка — по домену почты, а не по флагу в базе.

## Данные

| Хранилище | Что в нём | Почему так |
|---|---|---|
| **PostgreSQL, HA-кластер** | потребление и ключи шлюза, организации, кошельки, счета | там деньги и доступ; нужны репликация, бэкап и виртуальный адрес для переключения |
| **Redis** | кэш, очереди | обычная роль |
| **Векторная база** | эмбеддинги отдельных сценариев | продуктового RAG поверх неё нет — состояние как есть |
| **Объектное хранилище** | веса моделей, файлы, артефакты | делает GPU-бокс восстановимым и снимает веса с дисков ВМ |
| **Хранилище документов** | файлы клиентов в контуре РБ | часть продуктового предложения, а не инфраструктура |

Отдельно стоит перенос базы шлюза из тома на машине в общий HA-кластер: до него потеря одной машины означала потерю ключей клиентов и данных для выставления счетов одновременно.

## Наблюдаемость

- **Трассировка LLM-трафика** — отдельный сервис; хранит промпты и ответы, поэтому по чувствительности равен диалогам пользователей.
- **Метрики и дашборды** — общая система метрик площадки.
- **Ошибки приложений** — отдельный сборщик.
- **Доступность** — внешняя статус-страница и проверки.
- **Веб-аналитика** — посещаемость лендинга и чата, в контуре РБ (не внешний счётчик — по той же причине, по которой существует вся платформа).

Чего в наблюдаемости **нет**: сквозного распределённого трейсинга через все продукты. Путь запроса виден по частям — на шлюзе и в трассировке LLM, но связать их с действиями пользователя в чате одним идентификатором сегодня нельзя. Для разбора инцидента это означает ручное сопоставление по времени.

## Периметр

Обратный прокси перед всем: терминирует TLS, маршрутизирует по именам, отдаёт статику вроде подтверждений для мобильного приложения.

Сертификаты — Let's Encrypt; для поддоменов используется **wildcard, выпущенный через DNS-01**. Причина конкретная и стоит упоминания: выпуск по каждому имени отдельно упёрся в ограничение удостоверяющего центра на число сертификатов для одного идентификатора в неделю. Wildcard — это отдельный идентификатор, он покрывает и все будущие поддомены разом.

Прокси остаётся перед кластером и после переезда: он же и есть механизм переезда — цель для имени меняется в одном месте.
