# ДЗ 03. Разработка стратегии, оценка рисков и дорожной карты AI-проекта

> **Дано** (из ЛК OTUS). **Сдать до:** 14.05.2026. **Преподаватель:** Николай Осипов.

## Цель
Разработать стратегию внедрения AI-решения с выбором контрактной модели, оценкой рисков и дорожной картой для согласования с заказчиком.

## Кейс
**«Ритейлер и AI-рекомендации»** — клиент (крупный ритейлер) хочет внедрить AI-систему персонализированных рекомендаций, но требования размыты («хотим как у Ozon»). Полное описание кейса — в [PDF из ЛК](https://cdn.otus.ru/media/public/10/a0/%D0%9E%D0%BF%D0%B8%D1%81%D0%B0%D0%BD%D0%B8%D0%B5_%D0%BA%D0%B5%D0%B9%D1%81%D0%B0__%D0%A0%D0%B8%D1%82%D0%B5%D0%B9%D0%BB%D0%B5%D1%80_%D0%B8_AI_%D1%80%D0%B5%D0%BA%D0%BE%D0%BC%D0%B5%D0%BD%D0%B4%D0%B0%D1%86%D0%B8%D0%B8-252831-10a06e.pdf).

## Шаги выполнения

1. **Анализ требований.** Сформулировать **5–7 уточняющих вопросов** клиенту для снятия неопределённости.
2. **Выбор контракта.** Обосновать модель (**T&M, FP или гибрид**) для этапа PoC и для основной разработки. Пояснить, почему это выгодно обеим сторонам.
3. **Оценка рисков.** Матрица рисков — минимум 5 рисков, специфичных для AI (качество данных, галлюцинации модели и т.п.). Для каждого — план митигации.
4. **Roadmap.** Дорожная карта с критериями успеха (DoD) для этапов:
   - **PoC** (проверка гипотезы)
   - **MVP** (выход на пользователей)
   - **Production** (масштабирование)

## Критерии оценки («Принято», если)
| Критерий | Что значит |
|---|---|
| **Обоснованность** | Выбор типа контракта логично вытекает из уровня неопределённости |
| **Полнота** | Roadmap покрывает все три стадии (PoC, MVP, Production) |
| **Реалистичность** | Риски специфичны для AI, а не общие фразы |
| **Структура** | Документ читаем и понятен для бизнеса |

## Компетенции
Анализировать проектные ограничения и требования для выявления рисков и разработки плана проекта, разбитого на этапы с измеримой бизнес-ценностью:
- Аргументированно обосновывать выбор коммерческой модели контракта (FP, T&M, T&M with a cap).
- Составлять матрицу рисков и черновик Change Request для проектов с фиксированной ценой (FP).
- Разрабатывать дорожную карту проекта, декомпозируя задачи на этапы PoC, MVP и Production.
