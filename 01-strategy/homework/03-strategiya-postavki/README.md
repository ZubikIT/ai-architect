# ДЗ 03. Разработка стратегии, оценка рисков и дорожной карты AI-проекта

> **Условие из ЛК OTUS.** **Сдать до:** 14.05.2026. **Преподаватель:** Николай Осипов.

## Цель
Разработать стратегию внедрения AI-решения с выбором контрактной модели, оценкой рисков и дорожной картой для согласования с заказчиком.

## Описание / Пошаговая инструкция выполнения

### Легенда
Вы — архитектор в компании-интеграторе. Клиент (крупный ритейлер) хочет внедрить AI-систему персонализированных рекомендаций, но требования размыты («хотим как у Ozon»). **Описание кейса** вы найдёте в доп. материалах к этому занятию (см. ниже секцию «Полезные материалы»).

### Шаги выполнения

**1. Анализ требований.**
На основе легенды сформулируйте **5–7 уточняющих вопросов клиенту** для снятия неопределённости.

**2. Выбор контракта.**
Обоснуйте выбор модели (**T&M, FP или гибрид**) для:
- этапа **PoC**;
- **основной разработки**.

Поясните, почему это выгодно **обеим сторонам**.

**3. Оценка рисков.**
Составьте **матрицу рисков** (минимум **5 рисков**), специфичных для AI (например: качество данных, галлюцинации модели, дрейф, безопасность ПДн и т.п.).
Для каждого риска — **план митигации**.

**4. Roadmap.**
Разработайте **дорожную карту**. Опишите **критерии успеха (DoD)** для этапов:
- **PoC** (проверка гипотезы);
- **MVP** (выход на пользователей);
- **Production** (масштабирование).

## Критерии оценки

Статус **«Принято»**, если:

| Критерий | Что значит |
|---|---|
| **Обоснованность** | Выбор типа контракта логично вытекает из уровня неопределённости |
| **Полнота** | Roadmap покрывает **все три** стадии (PoC, MVP, Production) |
| **Реалистичность** | Риски **специфичны для AI-проектов**, а не общие фразы |
| **Структура** | Документ **читаем** и понятен для бизнеса |

## Компетенции

Анализировать проектные ограничения и требования для выявления рисков и разработки плана проекта, разбитого на этапы с измеримой бизнес-ценностью:

- аргументированно обосновывать выбор коммерческой модели контракта (**FP, T&M, T&M with a cap**) для конкретного проекта;
- составлять матрицу рисков и черновик Change Request для проектов с фиксированной ценой (FP);
- разрабатывать дорожную карту проекта, декомпозируя задачи на этапы **PoC, MVP и Production**.
