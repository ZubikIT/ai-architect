## Программа занятия (из ЛК)

### Цели занятия
- Изучить **стратегию реализации проекта**.
- **Декомпозировать большую задачу** на этапы, каждый из которых приносит измеримую ценность и снижает риски для дальнейшей разработки.

### Краткое содержание
1. **Этапы поставки ценности** — архитектурные компромиссы и бизнес-цели каждого этапа.
2. **Demo** — проверка гипотезы «как это будет выглядеть» (часто просто фасад).
3. **Proof of Concept (PoC)** — проверка технической гипотезы, валидация технологий, паттернов и выполнимости («Data Challenge», EDA).
4. **Minimum Viable Product (MVP)** — проверка рыночной гипотезы с минимальным набором функций для реальных пользователей.
5. **Связь стратегии с контрактом** — поэтапная поставка (например, **PoC по T&M, основной проект по FP**) помогает управлять рисками и бюджетом.
6. **Путь в Production** — полный жизненный цикл решения: окружения Dev / Test / Prod и их архитектурные особенности.
7. **Практика:** разработка дорожной карты проекта с AI-рекомендациями — бизнес-цели, scope, архитектурные решения и риски для этапов **PoC / MVP / Production**.

### Этапы поставки ценности
| Этап | Что проверяем | Аудитория | Бизнес-цель | Архитектурные компромиссы |
|---|---|---|---|---|
| **Demo** | «Как это будет выглядеть» | Заказчик, sales | Buy-in | Фасад, mock-данные |
| **PoC** | Техническую гипотезу | Архитектор, DS | Снять технический риск | Минимум инфраструктуры, фокус на одном пайплайне |
| **MVP** | Рыночную гипотезу | Реальные пользователи | Получить feedback | Production-grade, но узкий scope |
| **Production** | Масштабирование, SLA | Все пользователи | Регулярная бизнес-ценность | HA, observability, MLOps |

### Связь стратегии с типом контракта
| Этап | Рекомендуемый контракт | Почему |
|---|---|---|
| PoC | T&M (или T&M with a cap) | Высокая неопределённость |
| MVP | Гибрид / поэтапный FP | Часть scope понятна |
| Production | FP по фичам, T&M на R&D | Известные требования |
